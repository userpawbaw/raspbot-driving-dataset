# Raspbot 시간 맥락 비교

`models/`에는 legacy 입력으로 조작만 학습한 8개와, 같은 조작에 원래 mode 라벨을 보조 목표로 사용한 8개가 들어 있다. 모든 모델은 영상만 입력받는다. `with_mode_*`는 조작과 모드를 함께 출력하고, 런타임은 조작 출력으로 주행한다. 녹화된 모드 라벨을 그대로 사용했으며 자율주행 중인 모델에 모드 라벨을 입력하지 않는다.

| 파일명 끝부분 | 시간순 입력 |
|---|---|
| recent5, recent10, recent15 | 중복을 제거한 최신 연속 5장, 10장, 15장 |
| stride015, stride020, stride030 | 현재 1장과 각각 0.15초, 0.20초, 0.30초 간격의 과거 4장 |
| hybrid030, hybrid020 | 최신 연속 5장의 가장 오래된 시각을 기준으로 각각 0.30초, 0.20초 간격의 과거 5장, 그리고 최신 연속 5장 |

각 파일의 저장 샘플 주기는 목표 10Hz다. 개별 카메라 프레임의 촬영 시각 중앙 간격은 약 68ms이며, 주로 초당 약 15장이 촬영됐다. 따라서 연속 5장, 10장, 15장의 전형적인 시간 폭은 각각 약 0.27초, 0.61초, 0.95초다. 하이브리드의 시간 폭은 약 1.77초와 1.27초다. 간격형 프레임은 목표 시각에 가장 가까운 실제 프레임을 고르며 시각 오차가 55ms를 넘으면 해당 입력을 제외했다.

## 결과 읽기

| 프레임 구성 | 모드 제외 | 모드 포함 |
| --- | ---: | ---: |
| 연속 5장 | 83.9% | 84.0% |
| 연속 10장 | 85.0% | 84.2% |
| 연속 15장 | 83.9% | 81.7% |
| 0.15초 간격 | 83.1% | 83.7% |
| 0.20초 간격 | 83.5% | 82.7% |
| 0.30초 간격 | 84.2% | 81.7% |
| 연속 5장 + 0.30초 간격 5장 | 83.1% | 81.7% |
| 연속 5장 + 0.20초 간격 5장 | 84.1% | 83.0% |

- `results.csv`에는 4번 녹화 세션의 최종 평가가 들어 있다. 아래 수치는 직진과 좌회전의 평균 재현율이다. `test_WA_balanced`는 직진과 제자리 좌회전 재현율의 평균이다. `test_mode_balanced`는 NORMAL과 RECOVERY 재현율의 평균이다. 공란은 해당 라벨의 평가 샘플이 없거나 그 모델이 해당 출력을 제공하지 않는 경우다.
- `metrics.json`에는 클래스 수, 혼동 행렬, 증강 실험별 검증 결과가 있다. 조작 순서는 `W / A / D / S`, 모드 순서는 `NORMAL / RECOVERY`다. 혼동 행렬은 실제 라벨이 행이고 예측 라벨이 열이다.
- 1번과 3번의 일부를 훈련에, 2번과 3번의 8번 복귀 구간을 모델 선택에 썼다. 4번은 모델 선택에 사용하지 않았다. 파일 길이는 서로 다르며 모델 16개 모두 동일한 유효 시점으로 비교했다. 동일 세션의 legacy와 mode 사본을 분할 사이에 중복 사용하지 않았다.
- 정지 프레임은 맥락에 사용했고 조작 정답에서는 제외했다. 실차 운용 중의 정지는 기존 수신기와 키보드의 제어 기능으로 처리한다.
- 두 가지 증강을 각 모델에 시험했다. 기본은 색·채도·명암 증강이다. 강화는 여기에 일부 그레이스케일, 작은 위치 이동, 영상 노이즈, 더 큰 dropout과 weight decay를 추가했다. 클립 전체에 같은 변환을 적용했다. 좌우 반전은 조작 의미를 바꾸므로 사용하지 않았다. 클래스 가중, 라벨 스무딩, 조기 종료를 적용했다.
- 공통 맥락 조건을 적용하고 나면 훈련 후진은 5개 틱뿐이다. 검증용으로 떼어낸 나머지 4개 후진 틱은 앞선 촬영 공백으로 공통 맥락을 만들 수 없었고, 4번 세션에는 후진 자체가 없다. 우회전 역시 훈련 5틱과 최종 평가 23틱이다. 후진과 우회전의 실차 성능 판단에는 추가 시범이 필요하다. 모드 평가는 기록된 토글 라벨의 재현율이다. 모드 출력의 판정 임계값은 내부 검증에서 보정했다. 보정 전후 결과는 metrics.json의 mode_calibration에서 확인할 수 있다. 이 보정은 조작 출력에 영향을 주지 않는다.

## Raspberry Pi에서 실행

압축을 푼 뒤 이 폴더에서 실행한다. `runtime/`의 수신기가 ONNX 메타데이터를 읽어 학습과 같은 방식으로 프레임을 선택한다. 기존 수신기가 인식하는 이전 ONNX도 이 수신기에서 사용할 수 있다.

```bash
python runtime/raspbot_receiver.py --model models/legacy_recent10.onnx --speed 60 --pan 15 --tilt 100
```

조작 PC에서는 기존과 동일하게 아래를 실행한 뒤 Space로 시작한다. IP는 실제 값을 넣는다.

```bash
python runtime/raspbot_keyboard.py 192.168.1.11 --auto
```

긴 입력은 자동 주행을 시작한 뒤 필요한 프레임이 쌓일 때까지 정지 상태로 대기한다. 제공된 모델은 오프라인으로 평가했다. Raspberry Pi 실차 주행은 별도다.

다시 학습할 때는 NumPy, PyTorch, ONNX, ONNX Runtime을 설치한 환경에서 쌍을 이루는 NPZ 8개가 있는 폴더를 넘긴다.

```bash
python train_models.py /path/to/npz --output ./rerun
python calibrate_modes.py /path/to/npz --output ./rerun
```
